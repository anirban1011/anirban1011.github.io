Web application

KuberKosh

A simple and secure digital wallet for everyday small payments, with spending charts and two-step login. It lets you top up from a bank account and pay friends without filling your bank statement with tiny entries.

Why it exists

The problem and the solution

The problem

  • Insecure logins — simple apps often mishandle passwords and sessions.
  • Cluttered statements — small purchases fill bank records with dozens of entries.
  • No overview — most payment tools don't show where your money goes.

What KuberKosh does

  • Three layers of protection — Google sign-in, a time-based code (TOTP) and a PIN that is hashed before it is sent.
  • A separate wallet — your bank shows one top-up; the small payments stay in the wallet.
  • Instant insights — live charts of spending by category and balance over time.

Features

What you can do

Dashboard

Hide or show your balance with one tap, see a spending donut chart by category and a balance trend over a week or a month.

Add and withdraw money

Link a bank account with a clear confirmation step. Withdrawals need your PIN.

Send money to friends

The receiver's wallet is checked instantly, without reloading the page, to prevent mistakes.

Receipts and QR requests

Download a PDF receipt for each payment, or create a QR code with an amount that fills in the payment form when scanned.

Built with

Technology

BackendPHP with server-side sessions and MariaDB (third normal form), managed with phpMyAdmin
FrontendHTML5, SCSS and JavaScript, compiled with Webpack and Gulp; Bootstrap 5 for responsive layout
SecurityGoogle OAuth2, TOTP two-step login (RFC 6238), SHA-256 hashed PIN, prepared statements against SQL injection, HTTPS
HostingDocker containers on AWS EC2, behind Cloudflare for DDoS protection
ExtrasTCPDF for PDF receipts, QRCode.js for QR codes

Details

Reliability and next steps

Mistakes and edge cases it handles
  • Zero or negative amounts are rejected with a clear message.
  • Unexpected characters in amounts are blocked by strict number checks.
  • Overdrafts — the balance is checked before any update so a wallet can't go negative.
  • Clock differences between a phone and the server are tolerated for two-step codes.
Ideas for the future
  • AI-based budgeting suggestions from spending patterns.
  • Risk scoring to spot unusual activity, such as sudden location changes.
  • Tamper-proof, ledger-style transaction logs.
  • An open API so other apps can accept KuberKosh payments.
Run it yourself (for developers)

You need Docker, Docker Compose and Node.js. Then:

git clone https://github.com/anirban1011/KuberKosh.git
cd KuberKosh
npm install
npm start
docker-compose up -d --build

Create a .env file from .env.example with your database details and Google OAuth keys, then open http://localhost:8080. See the repository for the full steps.

FAQ

Common questions

How does KuberKosh handle passwords?

Sign-in goes through Google's official OAuth2 login, so KuberKosh never sees or stores your password.

Why is there a PIN if there's already two-step login?

Two-step login (TOTP) protects your account when you sign in. The six-digit PIN is a separate approval for each payment or withdrawal, so a stolen session still can't move money.

What happens if the network drops during a transfer?

Each transfer gets a unique ID before any balance changes. If something fails halfway, the database rolls everything back and the attempt is recorded as "Failed" with the reason, for auditing.

Why MariaDB instead of MongoDB?

Money needs strict, consistent records (ACID transactions), and relational tables with joins fit that well. The schema is in third normal form to avoid duplicate or conflicting data.

How was it tested?

With unit tests, integration tests and BurpSuite, a tool for intercepting and tampering with web requests, to check cases such as negative amounts and injected characters.
